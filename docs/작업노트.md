## 태효가 할 일

0. **운영 D1의 테스트 기록 지우기(중요)**: 배포 주소에서 E2E를 처음 돌릴 때 `sendBeacon` 이 Playwright 의 요청 가로채기를 피해 나가서, 테스트 기록(클리어 14건, 관람객 26)이 운영 DB에 들어갔다. 전부 개발자 해법 그대로의 테스트 기록(실제 관람객 없음, 배포 직후). 지우는 명령은 자동 모드 권한에서 막혀 실행하지 못했다. 아래를 직접 실행:
   ```bash
   npx wrangler d1 execute notwhatiasked --remote --command "DELETE FROM clear_hist; DELETE FROM fail_hist; DELETE FROM stats_cache; UPDATE counters SET value = 0 WHERE name = 'visitors';"
   ```
   (재발 방지: E2E·스크린샷 도구는 이제 배포 주소에서 `sendBeacon` 자체를 빈 함수로 바꿔 돈다. 고친 뒤 배포 주소 E2E 26개를 다시 돌려 DB 쓰기 0건 확인.) 지금 상태로도 표본 30명 미만이라 %는 안 보이고, 관람객 번호만 약 27번부터 시작한다.
1. **Cloudflare Fail open 확인**: 대시보드 → Workers & Pages → notwhatiasked → Settings → Runtime → **Fail open** 인지 확인(Functions 무료 한도를 넘어도 정적 페이지는 계속 서비스). president5 와 계정의 Workers 무료 한도(하루 10만 요청)를 공유함.
2. **한국어 GPT-2(KoGPT2)**: 환경변수 `HF_TOKEN` 이 없어 ONNX 변환·업로드 단계를 건너뜀. 지금 한국어 GPT-2 관은 영어 원본 GPT-2로 열림(화면에 안내 문구 있음).
   - 할 일: Hugging Face 토큰(쓰기 권한) 만들기 → Windows 환경변수 `HF_TOKEN` 등록 → 아래 "KoGPT2 변환 방법" 실행 → `content/gpt2/models.json` 에 `"ko"` 항목 추가 → 한국어 GPT-2 미션 8개 탐색(`npx tsx tools/gpt2-search.ts`, 스펙은 `tools/mission-specs.ts` 에 `gpt2Ko` 추가) → `ENGINE_VERSION` 올리고 배포.
   - 라이선스: CC BY-NC-SA 4.0(비상업). 변환본도 같은 라이선스·원저작 표기로 올릴 것. **광고·후원 붙이면 교체 필요.**
3. **D1 마이그레이션 주의**: `migrations/0001_init.sql` 은 기록용. 원격 DB에는 이미 같은 스키마가 있으니 `wrangler d1 migrations apply --remote` 는 **실행하지 말 것**(clear_hist 를 다시 만들려다 실패함). 로컬 테스트(`--local`)만 사용.
4. **공개 저장소와 해법**: GitHub `coomind/notwhatiasked` 는 지시대로 public. 미션 JSON(`content/missions`)과 `docs/미션표.md` 에 개발자 해법이 들어 있어 저장소를 보면 정답을 알 수 있음(게임 화면·배포 번들에는 해법이 없음 — 빌드 때 지움). 신경 쓰이면 저장소를 private 으로 바꿔도 배포에는 영향 없음(배포는 로컬에서 `npm run deploy`).
5. (선택) 커스텀 도메인은 아직 없음. 붙일 때 `tools/postbuild.ts` 와 `index.html` 의 OG 이미지 주소(`https://notwhatiasked.pages.dev/...`)도 같이 바꾸기.

## 판단 근거 (막혔을 때 고른 쪽)

### 폴더·저장소
- `기획서.md`·`개발프롬프트.md` 는 "옮겨라"였지만 원본 폴더(`멍청한 AI같으니라고`) 파일을 지우지 않으려고 **복사**했다(`docs/`). 원본은 그대로 있음.
- 브라우저 프로필(GPT-2 모델 캐시 128MB)은 OneDrive 동기화를 피하려고 OS 임시 폴더(`%TEMP%\notwhatiasked-chrome-profile`)에 둠.
- Playwright 브라우저는 내려받지 않고 시스템 Chrome(`channel: 'chrome'`)을 씀.

### 규칙 해석
- **도전모드 '시도'** = AI에게 보낸 입력 수(한 대화, 최대 5번). 일반모드 '몇 번 만에' 도 보낸 입력 수(판을 다시 시작해도 누적).
- **chars** = 클리어한 그 판의 입력 글자 수 합(grapheme, 공백 포함). 입력은 앞뒤 공백을 지우고 연속 공백을 하나로(GPT-2가 공백에 민감해서 모든 관에 같은 규칙).
- **maxTurns** = 일반모드 한 판의 턴 수(ELIZA 3, 마르코프·GPT-2 5). 도전모드는 미션과 상관없이 5번.
- 도전모드 결과는 브라우저 저장소 기준 첫 도전만 서버로 보냄(그 뒤는 '연습' 표시).
- ELIZA 기억 미션(the fact that)은 목표 문구가 기억 기능으로만 나오도록 골라서 'N번째 턴 이후' 같은 추가 규칙 없이 기존 미션 형식 그대로 씀.
- 금지어 판정은 지시대로 공백·구두점을 지우고 부분 문자열로 본다. 그래서 낱말 경계를 넘어 걸리는 경우도 있음(예: 금지어 pine 일 때 "ship in each"). 입력창 빨간 밑줄로 바로 보이므로 그대로 둠.

### 엔진
- **결정론**: 모든 랜덤은 `seed = hash(missionId + 지금까지의 입력들)` 의 mulberry32. eslint 규칙 + 테스트로 `Math.random` 금지.
  - elizabot.js 의 Math.random 4곳을 시드 PRNG 주입으로 바꿈(vendor/README.md). 원조 순서(랜덤 끔)로 돌리면 기획서에서 확인한 대답 4개가 그대로 나옴(테스트).
- **한국어 ELIZA**: elizabot 은 정규식 `\b` 로 낱말을 찾아 한글에서 안 됨 → 같은 데이터 구조(keywords·decomp·reasmb·$기억·goto·synons·pres·quits)를 어절 단위로 매칭하는 엔진(`agglu.ts`)을 새로 만들고, 규칙은 `content/eliza/ko.json` 데이터로 둠(일본어 등은 데이터 파일만 추가).
  - 조사: 받침 조건(이/가, 은/는…)까지 보고 떼어 냄("나이"를 나+이로 자르지 않음). 반사 후 조사를 새 낱말 받침에 맞춰 다시 붙임(나는→당신은).
  - 어미: 존댓말·반말(입니다/이에요/야/습니다/ㅂ니다/해요/해/어요/었어…)을 기본형으로 바꿔 "~다고/~라고" 로 되묻고, 모르는 어미는 직접 인용(“…”라고)으로 대신함.
- **마르코프**: 처음엔 30단어를 끝까지 이어 써서 아무 낱말이나 넣어도 우연히 목표가 나오는 문제가 있었음 → **문장이 끝나면(. ! ?) 멈추도록**(최대 30단어는 유지). 그래도 해법 탐색이 찾은 최단 해법은 운 좋은 시드 조합(예: "w" 한 글자)이라 '개발자 기록'이 매우 짧음 — 정상(전부 진짜 클리어).
  - 단어 분리는 지시의 `Intl.Segmenter` 대신 같은 결과를 내는 정규식을 씀. 브라우저마다 ICU 버전이 달라 Segmenter 결과가 다르면 서버 리플레이 검증이 깨지기 때문.
  - 한국어 학습 글: 나도향 「벙어리 삼룡이」는 위키문헌에 본문 텍스트가 없어(스캔 색인뿐) 이효석 「메밀꽃 필 무렵」(1942 사망)으로 대체.
- **GPT-2**: 지시대로 `Xenova/gpt2`, `dtype: 'q8'`, `model_file_name: 'decoder_model_merged'`, `max_new_tokens: 25`, `do_sample: false`, Web Worker, WASM 고정(스레드 1개).
  - onnxruntime-web 의 wasm 파일(26MB)이 번들에 복사되면 Cloudflare Pages 파일 한도(25MiB)를 넘어서, 번들에서는 빼고 transformers.js 기본값대로 jsDelivr CDN 에서 받게 함.

### GPT-2 브라우저 vs Node (중요)
- Node(onnxruntime-node, 네이티브 CPU)와 브라우저(onnxruntime-web, WASM) 출력을 18개 프롬프트로 비교 → **14개 같고 4개 다름**. 다른 4개는 모두 처음 몇~수십 글자는 같다가, 양자화(q8) 모델에서 확률이 거의 같은 두 토큰 중 다른 쪽을 고르면서 갈라짐(수치 커널 차이: 네이티브 CPU EP 와 WASM 커널의 부동소수 누적 순서 차이).
- Node 쪽을 WASM 으로 맞추려 했으나 transformers.js Node 빌드는 `cpu/dml/webgpu` 만 지원(`wasm` 미지원)하고 웹 빌드는 Node에서 안 돌아서 **Node를 브라우저에 맞추는 건 실패**.
- 해결: 플레이어가 실제로 쓰는 쪽(브라우저 WASM)을 기준으로 삼음. 해법 탐색(`gpt2-search.ts`)과 `test:missions` 는 **헤드리스 Chrome 안에서 이 게임의 GPT-2 워커를 그대로 돌려** 확인(`tools/lib/gpt2-browser.ts`). Node 기준으로 찾았던 해법 중 브라우저에서 안 통하는 2개(Shakespeare, banana)는 브라우저 기준으로 다시 찾음.
- E2E 비교 테스트는 ① 브라우저 출력이 다른 브라우저 세션에서 기록한 출력과 글자 하나까지 같은지(필수), ② 미션 해법이 브라우저에서 통하는지(필수), ③ Node 네이티브와 몇 개가 같은지(참고, `tools/search-logs/gpt2-node-vs-browser.json`)를 본다.
- 남은 위험: Safari 26 미만(WebGPU 없음)은 transformers.js 가 다른 wasm 변형(asyncify 아님)을 받는다. 같은 커널이라 결과가 같을 것으로 보지만 실제 Safari 에서는 확인하지 못함.

### 통계·한도
- Functions 는 세션당 최대 2번(GET /api/stats 1시간 캐시, POST /api/report sendBeacon 1번). 기록이 더 생기면 다음 세션에 보냄.
- 서버 리플레이 비용: Workers 안에서는 요청 중 시계가 멈춰 직접 잴 수 없음 → Node 측정값(초기화 2~3ms, 입력당 0.02~0.1ms, `tools/bench-replay.ts`)에 2배 여유를 두고 '예상 ms'(한도 7ms)를 더해 가며, 넘는 건은 리플레이 없이 verified=0 으로 기록.
- 리플레이가 안 맞는 기록(입력 조작)은 버림. GPT-2 는 verified=0, 통계에서 위아래 1% 잘라냄.
- 배포 주소 E2E 는 실제 통계를 더럽히지 않게 `/api/report` 만 막고 돌림(통계 조회는 실제로 호출).

### 공유·언어
- OG: 링크 미리보기 크롤러는 언어를 보내지 않으므로 기본 주소(/)는 영어 OG, `/ko/` 는 한국어 OG(빌드 때 `dist/ko/index.html` 생성). 공유 링크에는 lang 을 넣지 않음.

## 막힌 것 / 남은 문제
- **KoGPT2**: HF_TOKEN 없음 → 건너뜀(위 '태효가 할 일' 2번). 한국어 GPT-2 미션 0개, 한국어 사용자는 영어 GPT-2 미션 8개를 원본 모드로 플레이.
- **Node ↔ 브라우저 GPT-2 차이**: 맞추지 못함(위 설명). 최종 비교 결과 18개 중 16개 같음(`tools/search-logs/gpt2-node-vs-browser.json`). 게임·검증은 브라우저 기준이라 플레이에는 영향 없음.
- **Safari·Firefox 실기기 확인 못 함**: E2E는 시스템 Chrome(데스크톱·모바일 크기)만. iOS Safari 에서 GPT-2(128MB, WASM) 메모리 부족 가능성 있음.
- **마르코프 개발자 기록이 아주 짧음**: brute-force 가 '운 좋은 시드'를 찾아서(예: rabbit 미션 1글자). 규칙대로 최단을 par 로 둠. 사람에게 자연스러운 해법(예: "the white" → rabbit 약 80%)은 미션표의 탐색 로그 참고.
- **기획서와 다른 점**: 점수는 이 프롬프트대로 '시도 횟수'(동점은 글자 수). 힌트는 일반모드에서 별 깎임 없이 자유(도전모드에서만 금지).
